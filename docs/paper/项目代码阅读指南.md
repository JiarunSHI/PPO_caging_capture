# PPO_caging_capture 项目代码阅读指南

本文档按“在线数据如何流动”的顺序解释当前正式方案。项目中保留了若干早期实验分支，阅读时应先抓住 V14 联合 PPO、状态弧先验和动态 Cage 推理三条主线。

## 1 建议阅读顺序

1. `configs/ur5e_dynamic_cage_inference.yaml`：先理解正式推理的频率、轨迹、视觉预热、切换阈值和失败条件。
2. `cage_system/dynamic_cage_inference.py`：沿一次动态推理看完整数据流。
3. `cage_system/trajectory/kalman.py`、`spline.py`、`cage/plane.py`：理解目标运动状态如何由视觉历史得到。
4. `cage_system/cage/candidates.py`、`internal_region.py`、`est.py`、`pipeline.py`：理解离线 Cage 标签和固定弧位置先验如何产生。
5. `configs/ur5e_jailer_joint_v14_full.yaml`：理解 PPO 的30阶段课程、奖励和动作尺度。
6. `cage_system/sim/jailer_env.py`、`learning/jailer_policy.py`、`learning/train_jailer.py`：理解强化学习环境、网络与训练循环。
7. `cage_system/control/constrained_differential_ik.py`：理解 Jacobian 粗调控制器。
8. `cage_system/jailer_cli.py` 与 `cli.py`：最后查看各命令如何连接上述模块。

## 2 配置与公共数据结构

### `cage_system/config.py`

- `load_config`：递归加载 `extends` 配置并合并父子 YAML。
- `_expand_jailer_three_phase_curriculum`：把十个位置阶段扩展为 masked、observed 和 joint-pose 三段共30个阶段。
- `validate_config`：检查频率、EST重复数、候选方向分支和训练契约是否一致。

### `cage_system/types.py`

定义目标观测、滤波状态、候选位姿、EST指标和监督标签等跨模块数据对象。遇到字段含义不清时，应先查看本文件，再追踪产生和消费该字段的函数。

### `cage_system/geometry.py`

提供旋转向量、齐次变换、坐标系正交化和位姿误差等通用几何操作。Base、TCP、Cage 和相机之间的变换最终都依赖这些基础函数。

## 3 目标视觉与运动状态估计

### `cage_system/perception/eye_on_hand.py`

负责 MuJoCo eye-on-hand RGB-D 渲染、目标像素/深度检测，以及相机坐标到 Base 坐标的转换。该模块输出三维目标中心观测，不直接产生 Cage。

### `cage_system/trajectory/kalman.py`

核心类 `ConstantAccelerationKalman3D`：

- `initialize_state`：使用五帧视觉拟合得到的9维状态和9×9协方差初始化滤波器；
- `transition`：建立恒加速度状态转移矩阵；
- `process_noise`：利用积分白噪声 jerk 构建过程噪声；
- `predict`：只推进状态和协方差；
- `update`：执行创新门判断和 Joseph 形式协方差更新。漏检或拒绝时保留预测状态。

### `cage_system/trajectory/online.py`

管理视觉历史、五帧 bootstrap、滤波器调用和历史质量状态。它是单帧 RGB-D 观测进入 Kalman 的主要入口。

### `cage_system/trajectory/spline.py`

`SharedCubicSpline3D` 对三维历史共享时间基函数：

- `fit`：拟合带正则的局部三次样条；
- `evaluate`：计算位置或任意阶导数；
- `kinematics`：统一输出位置、速度、切线、加速度和曲率。

### `cage_system/cage/plane.py`

`LocalMotionPlaneEstimator.estimate` 结合 PCA、小曲率退化处理、切线×加速度法向、上一帧法向和 Base 参考方向，生成连续稳定的局部运动平面法向。

## 4 Cage 候选与 EST 标签

### `cage_system/cage/candidates.py`

- `SpeedRadiusMapper.map`：把目标速度线性映射为候选半径，再执行限幅、低通和平滑变化率限制；
- `CandidateGenerator.construct_arc`：建立当前切线交点到局部曲线首个圆交点之间的严格劣弧；
- `sample_arc`：在劣弧上产生归一化候选位置；
- `build_poses`：令 Cage x 轴指向目标、z 轴取正运动平面法向，并变换为 TCP 目标位姿。

### `cage_system/cage/internal_region.py`

定义真实 U 形抓子内部区域，区分 inside、outside 和 opening escape。这里是 EST “保持”判据的真实来源，不存在正负30° Cap 扫掠体。

### `cage_system/cage/est.py`

`MujocoESTEvaluator.evaluate` 的数据流为：

1. 固定当前候选 Cage 位姿；
2. 以目标当前位置和线速度建立根节点；
3. 从低密度状态格选择父节点；
4. 施加扰动力/力矩并进行 MuJoCo 前向积分；
5. 检查越界、穿透和有限性；
6. 按真实抓子内部区域记录节点状态；
7. 返回占有率、逃逸率、非法率和完整树结构。

### `cage_system/pipeline.py`

这是离线几何标签主流水线。它依次执行轨迹状态读取、局部曲线与平面估计、候选生成、共享扰动带下的三次 EST、候选统计与标签保存。要理解“一个 label 是如何产生的”，重点阅读候选循环及 `est_repeat_count` 周围的逻辑。

### `cage_system/learning/state_arc_dataset.py`

负责当前“状态—归一化最优弧位置”数据集及先验分析。离线统计证明输入与最优弧位置相关性弱，因此正式在线推理使用固定 `alpha=0.4375`，而不是旧 Cage 网络。

## 5 UR5e 仿真和底层控制

### `assets/mujoco_menagerie/universal_robots_ur5e/scene_eye_on_hand.xml`

正式 MuJoCo 场景入口，包含 UR5e、本体执行器、固定在 link6/TCP 上的抓子和 eye-on-hand 相机。若视频中缺少抓子，应同时检查 XML 的 geom group 与渲染 scene option。

### `cage_system/sim/ur5e_control.py`

封装关节名称、qpos/dof/actuator 地址、TCP 正运动学、Jacobian、关节速度和位置伺服，是 Jacobian 与 PPO 共用的机器人接口。

### `cage_system/control/constrained_differential_ik.py`

`TimeConstrainedDifferentialIK.command`：根据 TCP 位姿误差生成任务空间速度，通过带正则和速度边界的最小二乘求关节速度；同时考虑关节位置余量和加速度约束。它用于正式推理中的长距离粗调。

## 6 PPO 环境、网络与训练

### `cage_system/sim/jailer_env.py`

`JailerLogicalVectorEnv` 在一套 UR5e MJCF 中维护多个独立逻辑槽位：

- `_sample_target`：按当前课程误差范围采样可达目标；
- `_state`：构建“TCP–Cage位置误差3 + 旋转向量3 + q6 + qdot6”的18维状态；
- `_position_quality`：计算精细指数与粗尺度反二次位置质量；
- `_pose_quality`：通过三个虚拟轴标记点计算纯姿态质量；
- `_reward_weights`：按相对成功阈值动态分配位置和姿态权重；
- `step`：执行关节动作、MuJoCo积分、奖励、成功/失败/超时判定，以及 MOVE50/MOVE100 统计。

### `cage_system/learning/jailer_policy.py`

- `JailerPPO2Trainer.sample_for_environment`：由 Actor 采样 tanh 动作，并按当前位姿误差乘以动态动作增益；
- `joint_action_gain`：将位置/姿态中较严重的归一化误差映射为动作幅度；
- `JailerPPO2Trainer.update`：一次性计算 GAE 和 Critic 标签，随后用独立 Adam 分别更新 Actor 与 Critic；Actor 使用 PPO clip、熵正则和 KL 提前停止，Critic 不受 Actor 提前停止影响。

当前正式动作模式是 `joint_pose_actor_dynamic_speed_ppo_only_v2`。文件中仍存在 residual、reference actor 等早期兼容类，但它们不是 V14 正式策略的数据路径。

### `cage_system/learning/train_jailer.py`

实现 rollout 采集、课程晋级、Critic 对齐、阶段过渡、断点恢复、best/latest/阶段 checkpoint 保存和训练历史写入。阅读时重点关注：

- `collect_logical_rollout`：50个逻辑槽位如何形成一次 update 的样本；
- `JailerCurriculum.observe`：最近窗口成功率和平均误差如何决定晋级；
- `_apply_stage_entry_transition`：masked→observed、position→pose 时哪些参数和优化器状态被保留或重置；
- `_save_checkpoint`：为什么每个晋级阶段均能独立复现。

## 7 正式动态推理

### `cage_system/dynamic_cage_inference.py`

这是理解系统最终行为最重要的文件。

- `CausalFixedAlphaCageReconstructor.update`：把单帧 RGB-D 观测依次送入在线滤波、局部样条、PCA平面、速度半径和固定 α 候选重建；
- `_near_object_initial_joints`：在目标初始运动趋势前方寻找观察初态，但不直接放到 Cage 目标上；
- `evaluate_dynamic_cage_tracking`：生成全程可见的开放轨迹，推进目标运动，按10 Hz触发视觉观测、按100 Hz执行 Jacobian/PPO，处理连续漏检并保存 JSON、NPZ、视频和实时窗口。

状态机的正式顺序是：

`visual_warmup_hold → cage_jacobian_approach → ppo_local_tracking`。

PPO 切换阈值来自 `configs/ur5e_dynamic_cage_inference.yaml`：位置误差小于15 mm且姿态误差小于45°。一旦进入 PPO，本次轨迹保持 PPO 模式，不在阈值附近反复切换。

## 8 命令入口与输出

### `cage_system/cli.py` 与 `cage_system/jailer_cli.py`

二者只负责参数解析和调用真实实现。建议先在命令帮助中找到子命令，再跳转到对应 `command_*` 函数和核心模块，不要把 CLI 当成算法主体。

主要命令与实现关系：

| 命令 | 主要实现 | 输出 |
|---|---|---|
| `generate-trajectories` | `trajectory/generator.py` | 轨迹 NPZ |
| `generate-labels` | `pipeline.py` | Cage 几何/EST 标签 |
| `generate-cage-state-arc-dataset` | `state_arc_dataset.py` | 状态—最优弧位置数据 |
| `train-jailer` | `train_jailer.py` | PPO checkpoint、history、阶段模型 |
| `evaluate-dynamic-cage` | `dynamic_cage_inference.py` | JSON、轨迹 NPZ、MP4 |
| `render-jailer-video` | `jailer_visualization.py` | 静态到达策略视频 |

## 9 阅读代码时应区分的三类数据

1. **轨迹真值**：只用于仿真推进目标、离线标签和实验审计，正式在线重建不能读取未来真值。
2. **视觉/滤波状态**：在线算法真正可访问的数据；速度、加速度、曲率和运动平面均由历史观测因果估计。
3. **控制目标与机器人状态**：重建的 Cage 位姿、TCP 位姿、关节角和关节速度；它们构成 Jacobian 或 PPO 的输入。

只要沿这三类数据追踪，就能快速判断某段代码是否造成未来信息泄漏，或是否把几何候选、EST 状态扩展与机器人控制混为一谈。
