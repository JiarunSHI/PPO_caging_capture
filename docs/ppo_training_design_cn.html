文档目的与结论摘要

本文整理当前项目中PPO2部分的完整训练思路，重点说明18维状态、共享Actor-Critic网络、六维有界关节增量、tanh变换后的概率密度、同一Cage目标奖励、GAE、裁剪更新、熵估计、检查点和冻结推理接口。本文描述的是当前代码，而不是脱离实现的通用PPO模板。

三个最重要的结论：
  1. 动作头按状态输出六维均值；六维 log_std 独立维护，但它是可学习、状态无关的参数，不是训练期间不变的常数。
  2. tanh 将无界高斯样本变成 (-1,1) 内的归一化动作。它提供有界接口，但最终安全仍由单次增量、关节速度和关节位置限制共同保证。
  3. PPO更新不对动作本身求最优值，也不穿过MuJoCo反向传播；已执行动作是固定样本，梯度通过该动作在新策略下的联合对数概率回传到网络参数。

1. 系统中的PPO位置

PPO不是Cage姿态预测器。冻结的Cage网络根据最近五帧目标历史状态预测当前时刻的六维Cage目标位姿；PPO接收该目标位姿以及机器人当前关节状态，输出六个关节的归一化增量。二者职责严格分开：

Eye-on-Hand RGB-D观测
    ↓
目标中心点转到Base坐标系
    ↓
五帧历史（每帧三维位置 + 线速度标量）
    ↓
冻结Cage网络（20维输入）
    ↓
当前Cage目标（六维TCP位姿）
    ↓
PPO状态（18维）
    ↓
PPO Actor → 六维有界动作 → UR5e关节命令 → MuJoCo执行
容易混淆的维度：Cage网络输入是5帧×每帧4维，即20维；PPO输入不是这20维，而是“Cage六维目标位姿 + 当前六关节角 + 当前六关节速度”，共18维。

2. 时间触发与一步交互

当前视觉配置使用20 Hz检测，即每50 ms完成一次视觉事件。一次新的PPO决策由一次完成的视觉更新触发，不存在独立于视觉的高频PPO推理循环。MuJoCo仍然按照MJCF中的小时间步积分执行器和机器人动力学，但这些子步只负责执行同一条关节命令。

  1. 视觉帧完成检测，更新五帧历史缓存。
  2. 冻结Cage网络预测当前Cage目标 C_t。
  3. 读取当前关节角和关节速度，构造状态 s_t。
  4. PPO只对 s_t推理一次，得到动作 a_t。
  5. 在当前50 ms区间内，MuJoCo通过多个小步执行同一关节目标命令。
  6. 使用动作前保存的 C_t评价动作执行结果，得到奖励 r_t。
  7. 区间结束时采集新RGB-D帧，产生 C_(t+1)，再构造 s_(t+1)。
s_t=[C_t, q_t, qdot_t] → a_t → MuJoCo执行50 ms → 用C_t计算r_t
                                           ↓
                                  新视觉帧得到C_(t+1)
                                           ↓
                              s_(t+1)=[C_(t+1), q_(t+1), qdot_(t+1)]

如果视觉观测超过配置的最大陈旧时间，当前实现将本次动作抑制为零，防止机器人依据过时目标继续运动。

3.3 均值与方差的准确含义

网络按状态输出六维均值 μ(s)。标准差来自单独的六维参数 log_std，通过指数转换为正数。它初始为 -0.7，对应初始标准差约0.497；训练时和网络权重一起更新。

“固定方差”的准确说法：它对所有状态使用同一组六维数值，因此是“状态无关方差”；但它不是“训练中不更新的方差”。确定性推理只使用 tanh(μ)，不再随机采样。

4. 从原始动作到物理关节命令

4.1 三个不同层次的动作

层次符号范围用途
原始高斯动作u无界从正态分布采样，便于连续策略学习
归一化动作a=tanh(u)(-1,1)网络与不同关节之间的统一有界接口
实际关节增量Δq受物理限制映射成每个视觉周期内的关节目标变化

4.2 训练采样

ui ∼ Normal(μi(s), σi2)
ai = tanh(ui)

六个维度采用对角高斯：给定状态后，各维原始动作条件独立，但共享同一个状态特征网络。

4.3 物理动作映射

当前一步持续时间由视觉频率决定。先计算每个关节在这个时间内按照速度上限允许移动的最大角度，再与配置的单视觉周期最大增量取更严格者：

safe_deltai = min(config_deltai, velocity_limiti × decision_dt)
q_command = clip(q_current + safe_delta × a, q_lower, q_upper)

默认视觉周期为0.05 s。配置的单步最大增量是前三关节0.09 rad、后三关节0.14 rad；同时还要服从每个关节的速度上限，最后再裁剪到关节位置上下限。

归一化的目的：
  • 让策略始终输出统一的无量纲范围，降低六个关节控制尺度差异带来的训练困难；
  • 让动作连续地接近边界，而不是使用硬裁剪直接截断高斯样本；
  • 保证发送到后续缩放层的动作有界；
  • 配合物理限幅防止超速、单步跳变和越过关节位置限制。
因此tanh本身不是完整的安全机制。

执行链中不存在“先tanh、再atanh还原、再执行”。atanh只在PPO训练阶段使用，用于由已经保存的实际动作恢复其原始高斯坐标，从而计算正确的概率密度。

5. tanh后的概率密度与Jacobian修正

5.1 密度不是离散概率

这里的“密度”就是连续概率密度。某个精确实数动作的概率为零；一个很小动作区间的概率，近似等于该处密度乘以区间宽度。密度本身可以大于1，只有对一个区域积分后才是0到1之间的概率。

5.2 为什么不能直接使用原始正态密度

tanh会改变空间尺度。在零点附近变化较快，而在接近±1时导数接近零：很宽的原始动作区域被压缩到很窄的实际动作区域。因此原始空间中“每单位u”的密度，不能直接当作实际空间中“每单位a”的密度。

u = atanh(a) = 0.5 × ln((1+a)/(1-a))
da/du = 1 - tanh²(u) = 1-a²
pA(a|s) = pU(atanh(a)|s) / (1-a²)

除以 1-a²就是变量变换的Jacobian修正，也可理解为你所说的“追溯tanh造成的密度压缩”。

5.3 六关节联合对数密度

六个关节是一次联合动作。对角高斯的联合密度是六个单维密度的乘积；代码使用对数后把六项相加，避免小数连乘下溢：

log π(a|s) = Σi=1..6 [ log Normal(atanh(ai); μi(s),σi²) - log(1-ai²) ]

代码从原始动作直接采用数值稳定恒等式计算 log(1-tanh²(u))，避免动作接近±1时出现 log(0)。更新阶段对已保存动作先裁剪到略小于±1，再执行 atanh。

梯度到底在哪里：Rollout里的实际动作是固定训练样本。新策略计算该固定动作的对数密度，梯度由对数密度流向μ、log_std和共享层。梯度不会通过MuJoCo，也不会把历史动作本身改掉。新熵样本采用重新参数化采样，熵项的梯度可以通过采样与tanh流回策略参数。

6. Rollout采集和同一Cage目标契约

6.1 每条transition保存的内容

数据作用
标准化状态 stActor和Critic更新输入
实际有界动作 at新策略重新评价同一动作
奖励 rt优势和价值目标
下一状态 st+1下一价值估计与时序连接
done终止时切断价值自举
旧联合对数密度计算新旧策略密度比
旧价值V(st)GAE和价值目标
下一价值V(st+1)TD残差；终止状态为0

6.2 同一Cage奖励契约

动作 a_t由包含 C_t的状态决定，因此奖励必须评价动作执行后的机器人相对于同一个 C_t的误差。区间末尾新视觉帧产生的 C_(t+1)只属于下一状态，不能反过来评价前一个动作。

采样代码逐步检查：

  • 奖励中记录的Cage位姿必须等于 raw_state[:6]；
  • 下一Cage位姿必须等于 raw_next_state[:6]；
  • 契约不满足时立即抛出错误，防止继续产生错误训练数据。

7. 奖励函数

当前奖励由TCP位置误差、TCP姿态误差和关节代价组成，并在发生接触碰撞时额外减去碰撞惩罚：

reward = -12 × position_error² -2 × orientation_error² -0.04 × joint_cost - collision_penalty

其中关节代价包含：

  • 关节接近限位的四次惩罚；
  • 当前关节速度平方惩罚；
  • 本步关节变化平方惩罚。

碰撞惩罚默认是20，并默认在接触碰撞时终止当前episode。位置和姿态误差始终针对产生当前动作的同一个Cage目标。

8. GAE、价值目标与优势归一化

8.1 时序差分残差

δt = rt + γ(1-donet)V(st+1) - V(st)

8.2 GAE优势

At = δt + γλ(1-donet)At+1

默认 γ=0.99、λ=0.95。GAE在一步TD的低方差和长回报的低偏差之间折中。Actor使用标准化后的优势，减少不同rollout奖励尺度变化对更新步长的影响。

8.3 Critic目标

Rλt = At + Vold(st)
Lvalue = 0.5 × mean((V(st) - Rλt)²)

Critic和Actor使用同一套GAE语义，不再混用另一套高方差的完整Monte Carlo回报。

9. PPO裁剪更新与熵估计

9.1 新旧策略密度比

ratiot = exp(log πnew(at|st) - log πold(at|st))

这是同一个六关节联合动作在新、旧策略下的密度比，而不是为六个关节分别构造六个PPO目标。

9.2 裁剪Actor目标

Lactor = -mean(min(ratio×A, clip(ratio,1-ε,1+ε)×A))

默认裁剪范围 ε=0.2。如果一个样本的策略变化已经超过允许范围，裁剪分支会限制它继续推动参数发生大变化，从而提高训练稳定性。

9.3 tanh实际策略的熵

未经变换的高斯熵不能准确反映实际有界动作的探索程度。例如原始高斯方差很大时，经过tanh后动作可能大量堆积在±1附近，看起来“高斯熵很大”，实际控制却接近两端饱和。

当前实现从策略重新参数化采样新的原始动作，经过tanh变量变换后计算：

H(π) = - Ea∼π[log π(a|s)]

使用Monte Carlo样本近似这个期望，并把变换后熵作为奖励项加入总损失。目的不是单纯增大高斯方差，而是鼓励实际可执行动作空间中的有效探索。

9.4 总损失和梯度

L = Lactor + 0.5Lvalue - 0.002H(π)

每个minibatch执行：

  1. 重新计算实际动作的联合对数密度、价值和熵样本；
  2. 计算PPO裁剪损失、价值损失和熵奖励；
  3. 对模型参数反向传播；
  4. 将全局梯度范数裁剪到0.5；
  5. 使用Adam更新共享层、动作均值头、价值头和log_std。

10. 训练循环、GPU分工与检查点

10.1 外层训练循环

默认执行500轮更新。每轮至少收集2048个完整episode组成的transition，然后进行最多10个epoch的重复更新，每个minibatch为128个样本。

初始化Actor-Critic、Adam和状态标准化器
for update in 1..500:
    收集不少于2048步的完整episode
    计算GAE和lambda-return
    for epoch in 1..10:
        打乱样本
        按128大小划分minibatch
        计算联合密度比、裁剪损失、价值损失、变换后熵
        检查KL，必要时提前终止本轮更新
        反向传播、梯度裁剪、Adam更新
    输出训练诊断指标
保存v8检查点和状态标准化统计

10.2 CPU与GPU的实际分工

工作主要设备说明
MuJoCo动力学步进CPU不是PyTorch张量计算，通常不会自动使用CUDA
RGB-D渲染OpenGL/EGL可能使用GPU图形管线，但不是PyTorch训练CUDA利用率
Cage网络推理CUDA（auto可用时）批量很小，单次占用可能不高
PPO网络前向与反向CUDA（auto可用时）72k参数网络较小，环境采样常是瓶颈

因此即使PPO使用GPU，整体训练仍可能由串行MuJoCo采样和视觉渲染限制，GPU利用率不会像大型监督网络训练那样持续接近满载。

10.3 检查点契约

当前保存格式版本为v8。检查点除模型参数外，还保存：

  • 18维状态、6维动作和隐藏层结构；
  • 运行均值/方差标准化统计；
  • tanh变换对角高斯联合密度契约；
  • tanh实际策略熵契约；
  • GAE lambda-return价值目标契约；
  • 同一Cage目标奖励契约；
  • 每次完成视觉更新只产生一个动作的触发契约；
  • Cage几何坐标契约。

加载冻结PPO时会逐项核对这些字段。不符合当前训练语义的旧检查点不会被静默加载，必须重新训练。

11. 诊断指标、当前检查结论与训练指令

11.1 每轮需要联合观察的指标

指标含义与判断
actor_loss策略裁剪目标；不能单独用其正负判断性能
value_lossCritic拟合lambda-return的误差
explained_varianceCritic解释回报变化的能力；长期接近或低于0需要排查
entropytanh后实际策略的微分熵，反映有效探索
density_ratio_mean新旧策略平均密度比，通常应在1附近
approx_kl / max新旧策略距离；过大触发提前停止
clip_fraction被PPO裁剪的样本比例；长期过高说明更新过猛
action_saturation_fraction|a|≥0.98的动作比例；过高表示动作长期挤在tanh边界
position/orientation error任务性能的直接指标，应按轨迹和时间统计
collision / stale vision安全和视觉闭环质量，不能被总回报掩盖

默认目标KL为0.02，超过0.03时提前停止当前轮的后续epoch。该机制和PPO比率裁剪共同限制一次更新过大。

11.2 当前代码结构检查结论

  • 通过：18维状态与6维关节动作契约一致。
  • 通过：均值头、可学习状态无关log_std和标量Critic结构合理。
  • 通过：使用六维联合对数密度，而非错误的逐关节独立PPO比率。
  • 通过：实际tanh策略密度包含稳定的Jacobian修正。
  • 通过：同一Cage位姿用于状态、动作条件和该动作奖励。
  • 通过：GAE优势、lambda-return价值目标和终止自举逻辑一致。
  • 通过：状态标准化统计保存并在推理时冻结。
  • 通过：关节命令同时受到tanh、单步增量、速度上限和位置限位约束。
建议重点监控而非立即改动：
  1. 如果动作饱和率长期很高，建议在rollout中额外保存原始动作u，减少由接近±1的动作反求atanh时的数值敏感性。
  2. 当前log_std不依赖状态，优点是简单稳定；如果后续证据显示不同轨迹阶段需要明显不同探索尺度，再考虑状态相关方差头。
  3. Actor和Critic共享特征层是标准且紧凑的设计；只有观察到明显梯度干扰时才需要拆分网络。
