# 动态 Cage 姿态维持系统方法设计

## 1. 固定的数据契约

目标物体统一抽象为中心点质点，不输入或估计目标姿态。全部目标数据、轨迹、候选端点和机械臂 TCP 位姿统一到 `base_link`，单位为米、秒和弧度。Base、link6、Cage、TCP 和相机三维坐标系全部采用右手系；图像像素的横右纵下只是一种二维存储约定，不改变相机三维坐标系的手性。

对标签时刻 `t`，Cage 网络只能读取严格早于当前时刻的五帧 `t-5 ... t-1`。每帧为 `[x,y,z,speed]`，其中 `speed` 是三维线速度向量的大小。因此原始输入形状为 `[5,4]`，展平后为 20 维；输出是当前 `t` 的六维 Cage TCP 位姿 `[x,y,z,旋转向量]`。完整未来曲线只服务于离线标签生成，绝不进入训练输入或在线推理输入。

冻结 Cage 网络以后，PPO2 状态保持为 Cage 预测位姿 6 维、UR5e 关节角 6 维和关节速度 6 维，共 18 维；动作是 6 个归一化关节增量。PPO2 不反向更新 Cage 网络。

## 2. 目标轨迹处理

### 2.1 数据输入和坐标转换

相机或检测器输入是带真实采集时间戳和 `frame_id` 的目标中心点。进入轨迹模块前按时间排序、去除重复时间戳、门控异常跳变并标记缺帧。在线 ROS 接口使用 `geometry_msgs/PointStamped`；COCO 检测框或分割掩码需要与深度、双目或点云结合才能得到三维中心点。

MuJoCo训练不再直接把目标真值坐标当作相机观测。UR5e腕部相机渲染RGB和米制深度，RGB检测器产生目标掩码，掩码内深度经过前景聚类后按针孔模型反投影，并使用MuJoCo给出的相机外参转换到Base。仿真几何分割只用于审计检测掩码，默认不参与中心估计。可配置深度噪声、像素丢失和整帧检测丢失。

每个点按该时间戳对应的 TF 从相机坐标系变换到 Base。TF 缺失、过期或外插过大时拒绝该帧。离线生成、数据回放和在线节点复用相同坐标、单位与时间处理规则。

MuJoCo 相机坐标系为右手系，光轴朝相机局部负 z；反投影时显式处理图像纵轴向下的符号，再用同一采集时刻的 `Base←Camera` 刚体变换得到 Base 点。每个旋转矩阵都要求正交且行列式为正，Cage 姿态构造采用 `y=z×x` 并重新计算 `x=y×z`，禁止用镜像矩阵伪装旋转。

### 2.2 九状态卡尔曼滤波

滤波状态由三维位置、三维速度和三维加速度组成。每次传播使用真实时间差，近似恒加速度模型只承担相邻时刻的短时传播，不约束完整轨迹形状。

有效测量先经过创新门控，再修正状态；明显跳变只保留预测结果并记录拒绝。短时缺帧执行预测传播并降低置信度；超过陈旧阈值后停止发布新控制目标。噪声参数从仿真、静态观测或训练集统计初始化，再通过验证集标定。

### 2.3 离线完整轨迹拟合

离线标签阶段可以读取整条已记录轨迹。先顺序运行卡尔曼滤波，再用全部滤波位置拟合共享时间节点的三维三次 B 样条。三个空间坐标使用同一时间参数和节点设置，使位置、速度和加速度保持一致。

控制点间距决定可以保留的转弯尺度，平滑强度抑制相机抖动。参数选择同时考察位置残差、转弯保留和导数稳定性，不能只追求穿过每个噪声点。结果是一条可按任意时间查询的连续三维曲线，不是一个未来点或一组互不关联的点。

### 2.4 速度、加速度和后续曲线

完整样条的一阶解析导数提供三维速度，速度向量长度提供网络所需的标量速度，归一化后得到切线；二阶解析导数提供加速度。低速时不归一化近零向量，而是沿用稳定切线、使用邻域曲线方向或把样本标为低速不确定。

每个离线时刻保存位置、速度向量、速度大小、切线、加速度、曲率、局部平面和置信度。从当前时间向后提取连续真实曲线段，短窗口不够时延长到配置上限；仍无法到达候选圆时将该半径样本标为无效。

### 2.5 在线滚动更新

在线端只能读取当前及过去观测。新点到达后更新卡尔曼和历史局部样条，较新点权重较大。卡尔曼速度与样条端点速度做保守融合，得到当前帧的速度大小；短时连续延伸仅供监控和安全分析，不进入 Cage 网络。

调用顺序必须是：缓存已有五帧时，先用缓存预测当前 `t` 的 Cage；随后才处理当前观测，并把新 `[x,y,z,speed]` 加入缓存。历史不足五帧时只积累和滤波。

## 3. Cage 候选和标签

### 3.1 局部运动平面

从当前位置邻域和平滑未来曲线采样点估计局部平面。弯曲明显时使用局部点拟合的稳定法向；接近直线时沿用上一法向，第一帧使用 Base 参考方向投影得到法向。新法向统一符号并渐进更新，避免相邻时刻翻转。

随机样本本身是平面轨迹。离线标签阶段先对完整平滑曲线做一次平面退化检查：如果完整曲线包含足够的二维弯曲信息，就使用整条曲线拟合的稳定法向作为该轨迹各时刻的平面法向；如果完整曲线近似一条直线，仍采用上一法向和 Base 参考方向策略。完整曲线法向只属于离线标签分支，不进入五帧网络输入，也不用于在线推理。

候选抓子端点坐标系 E 的 `x-o-y` 平面与运动平面重合，z 轴取法向正向或反向。正反分支由抓子结构、IK 和碰撞筛选决定。

### 3.2 速度到半径映射

系统只有一个候选半径，即目标中心到实际候选 Cage 端点的随动距离，不再构造投影半径或第二个评价位姿。默认把速度区间 0.05--0.45 m/s 线性映射到 0.100--0.180 m：低于速度下限取最小半径，高于速度上限取最大半径，中间保持正比例。配置中的速度上下限应覆盖训练轨迹速度分布，半径上下限则同时受相机视场、目标完整可见、机械臂工作空间和跟踪能力约束。

线性映射的原始半径先裁剪到上下限，再按真实时间进行低通和平滑变化率限制，避免相邻帧速度噪声引起候选圆跳变。因此静态标定曲线是严格线性的，沿时间实际输出则是受动态平滑约束的线性响应。当前最小半径还必须大于抓子开口深度、球半径和开口外安全间隙之和，以保持待抓取随动距离和眼在手上视野。速度标定通过速度分桶回放、目标每帧位移、视觉到动作延迟、TCP 跟踪滞后、候选有效率和相机可见率联合完成；最大轨迹速度必须低于实测 UR5e 可靠 TCP 速度除以安全系数。

### 3.3 候选圆、交点和劣弧

以当前目标中心为圆心、随动观察半径为半径，在局部运动平面内构造二维候选圆。圆只描述真实随动标签中抓子端点 E 的候选位置，不是三维捕获区域。

前向切线交点取当前切线正方向上的圆周点。未来交点沿真实后续曲线按时间前进，找到曲线第一次从圆内到圆外的区间，再插值或根搜索得到精确交点。名义搜索窗口为 1 s；还会根据随动半径与当前速度估计到达边界所需时间，并在必要时扩展，最大为 3 s。两个点必须投影回同一平面和圆周。

两交点间选短劣弧，候选弧的两个端点始终严格等于前向切线交点和未来曲线首次出圆交点，不再人为扩大或截断圆弧。接近直线导致交点重合时，劣弧退化为唯一的切线候选；法向连续化后再计算带符号弧方向，避免时间跳变。

### 3.4 弧上采样和六维姿态

劣弧包含两个边界和等角内部样本；上一最佳角仍位于弧内时，在其附近密集采样。最后排序、去重，并把每个点重新投影到圆和平面。

对每个端点，E 的 x 轴从端点指向目标中心，z 轴取平面法向分支，y 轴按右手系构造，然后整体正交化。由 Base 到 E 和固定 TCP—E 变换得到实际 Base 到 TCP 位姿。相邻姿态差使用三维旋转距离，不使用欧拉角分量差。

当前 MJCF 中 `wrist_3_link` 就是 link6。Cage 刚体固定在 link6 局部 `[0,0.1,0]`，固定旋转为绕 link6 局部 z 轴正向 90 度，使 Cage x 轴与 link6 的局部正 y 伸长方向严格同向。`attachment_site`、`cage_endpoint`、抓子几何和 eye-on-hand 相机都位于该固定刚体树下，运行时没有额外自由关节；因此 `link6←Cage`、`Cage←TCP` 和 `Cage←Camera` 都是时间不变的标定变换。

### 3.5 抓子真实内部区域

内部区域在 E 中由左右夹爪内表面、根部后边界、上下有效边界和开口方向共同定义。点质点中心转换到 E 后，对所有边界保留安全间隙。越过开口记为逃逸；越过左右、上下或根部自由边界记为碰撞或非法状态。开口只是逃逸界面，不是实体封盖。

随动候选的目标初始状态通常位于开口之外，这不构成几何拒绝，也不要求把候选平移到抓子内部。Cage 内部区域只是对 EST 已生成状态进行分类的固定 Capture set：节点在全部安全边界内记为 inside，越过开口或位于外部自由空间记为 outside，只有物理越界、数值非法或超过允许穿透才记为 illegal。同一个候选端点和姿态贯穿候选生成、机械臂筛选、EST 和标签输出。

### 3.6 几何和机械臂硬筛选

先检查候选圆半径残差、平面残差、姿态正交性、x 轴朝向目标、全部固定变换和相邻最佳位姿跳变。随后只对这个实际候选检查工作空间、IK、自碰撞、环境碰撞、初始不允许穿透、碰撞距离和可达余量，并满足关节位置、关节速度和视觉事件可提供的累计单步关节增量。目标根状态是否位于 Capture set 内不是硬筛选条件。

明显不可达或碰撞候选必须删除。`workspace` 后端仅供无机器人模型的流程自检；生产标签需使用 MoveIt 或加载真实 UR5e、抓子和环境 MJCF 的 MuJoCo 后端。

### 3.7 EST MuJoCo 动力学扩展

EST 以目标当前中心位置和线速度构成根节点，当前候选 Cage 在整个短时评价窗口中固定。根节点允许在真实内部区域之外，outside 节点也允许继续作为父节点；Capture set 归属是扩展后的节点标签，不是树的状态有效性约束。

每轮把全部未到时间上限且物理合法的节点，按候选 E 坐标系中的位置、线速度和角速度划分密度单元。父节点选择权重与所在单元密度相反，再使用预先生成的选择分位数抽样，促使树优先覆盖稀疏状态区域。选定父节点后恢复其完整 MuJoCo `qpos/qvel`，对球体施加随机 Base 系外力、随机力矩和随机作用时间，并用 MuJoCo 接触动力学逐小步前向积分。

每个积分步检查非有限状态、环境边界和最大允许接触穿透；只有这些物理非法状态停止该分支。传播结束后，把新节点按同一个候选抓子真实内部区域标为 inside、outside 或 illegal，并保存完整状态、父索引和树时间。循环持续到统一节点数或时间范围。每个候选默认执行3次独立EST；在每次重复内，所有候选复用相同外力、力矩、持续时间和父节点选择分位数。每个 worker 使用独立 MuJoCo `MjData`。

本实现参考本地《Caging in Motion》论文中“低密度 EST + 正式物理仿真 + 扩展后 Capture set 评分”的数据流，但按当前已确定方案不使用论文的能量似然或 Softmax 权重。目标虽按中心点输入网络，MuJoCo 中仍用具有质量、半径、自由关节和接触参数的球体代理进行正式动力学积分。

### 3.8 保持评分和最优标签

每次EST分别计算整棵树的内部节点比例，根节点也计入总数；同一候选3次结果取均值作为唯一动力学主分数，没有能量权重、Softmax、Cap概率或方差加权。主分数先确定近似最优集合，该集合内只比较两个次级量：首先选择六关节变化范数更小的候选，其次选择相对上一最佳TCP位姿连续性代价更小的候选。

连续性包含平移与旋转两部分。平移量是候选TCP位置与上一最佳TCP位置的直线距离；旋转量是两个旋转矩阵之间的三维几何夹角。两者分别除以配置的最大允许跳变0.12 m和55度，再等权平均为无量纲连续性代价。完全相同位姿的代价为0，数值越小越平滑；任一原始变化超过对应最大值时仍作为硬条件淘汰。第一条有效标签没有上一位姿，连续性代价记为0。

IK不可达、碰撞、关节越界、速度超限等仍是进入EST前的硬筛选条件，但可达余量、碰撞距离、关节限位余量、劣弧中点和EST方差不再参与最终候选排序。

最高保持比例低于阈值或全部候选硬失败时，该时刻没有标签。可以离线调整半径、采样密度或平面参数后重试，但不能强制选择无效候选。

### 3.9 监督数据生成

每条轨迹运行两个隔离分支：因果输入分支只顺序处理过去观测；标签分支使用完整平滑轨迹计算当前运动量和真实未来曲线。标签时刻到来前复制五帧因果缓存，候选与 EST 选择完成后，把最佳当前 TCP 六维位姿写为标签。

数据集保存输入 `[N,5,4]`、标签 `[N,6]`、轨迹编号、标签时间戳、输入语义、点质点模型、几何契约和格式版本。训练/验证按整条轨迹拆分。旧60维数据、旧大抓子标签、旧TCP构型和旧定时PPO检查点都会被格式校验拒绝。

为统一训练与推理，几何标签生成后还要执行视觉重放。每个历史时刻把目标放到真实轨迹中心，把UR5e相机移动到最近一个严格更早的可行标签位姿，再从实际渲染RGB-D恢复中心点并形成历史速度。当前标签只能在当前图像采集之后用于下一帧机器人位姿，因此不会通过相机姿态泄漏到当前输入。无法获得初始IK、目标不可见或历史不足的样本写入视觉审计并剔除。

## 4. Cage 网络、PPO2 和仿真

### 4.1 Cage 监督网络

Cage MLP 把 20 维输入送入默认 256、256、128 的 LayerNorm/SiLU 隐藏层，输出六维 TCP 位姿。输入使用训练集统计量标准化；位置用位置误差训练，旋转向量先转换为旋转矩阵后计算几何旋转误差。检查点保存模型参数、标准化量、输入形状、对象模型、位姿表示、最佳验证损失和训练历史。

训练入口支持 `--device auto`。有 CUDA 时选 `cuda:0`，否则使用 CPU；显式指定 CUDA 但进程看不到 GPU 时直接报错。

### 4.2 PPO2

冻结 Cage 网络在MuJoCo episode内对实时腕部RGB-D结果做严格因果推理，形成动态 TCP 目标。系统采用视觉事件驱动：相机20 Hz完成一次检测后，立即组装当前18维状态、执行一次PPO推理并发布一个六维关节增量；在下一帧视觉完成前不再次运行PPO。18维状态固定为Base下TCP到当前Cage的相对位置3维、最短旋转向量3维、关节角6维和关节速度6维。原始状态使用在线运行均值和方差归一化，rollout保存动作采样时实际使用的归一化状态，最终统计量冻结并写入检查点，MuJoCo和ROS推理都先应用同一统计量。

MuJoCo每个底层位置控制积分步为六个UR5e关节补偿模型偏置力，使零关节增量表示底层控制器维持当前位置，而不会因仿真执行器缺少真实UR控制器的重力补偿而持续下垂。该补偿在随机专家示范、C7 DAgger、Critic rollout、正式PPO和MuJoCo推理中完全一致。

Actor和Critic使用独立特征主干。正式PPO前先在与轨迹无关的随机无碰撞关节构型上构造固定局部Cage目标，由阻尼Jacobian专家采集短片段并只监督训练Actor；随后才接入视觉轨迹，每次从C7无碰撞IK构型开始，按80%、50%、20%、0%的专家执行权重完成四轮混合DAgger。每轮保存当前状态与纯专家动作并用完整聚合数据继续监督训练Actor。DAgger结束后重新创建Critic，从C7开始冻结Actor采集真实rollout并预热价值网络，最后清空专家阶段优化器状态并开始纯Actor的on-policy PPO。完整逻辑见`expert_training_pipeline_cn.md`。

Actor使用六维对角高斯和双曲正切限幅，保存实际执行动作的联合对数密度；更新时继续用新旧联合密度比并执行PPO截断。tanh以后动作分布的熵没有简单解析式，因此每个minibatch从当前高斯重新参数化采样，经tanh得到真实动作，再计算包含tanh Jacobian修正的联合对数密度，其负值作为实际有界策略熵的蒙特卡洛样本。minibatch内大量状态的样本均值形成熵奖励。该估计直接鼓励 `[-1,1]` 内的有效探索，避免只增大tanh之前的高斯方差、却让执行动作堆积在±1边界。

优势使用标量GAE，Critic目标使用同一GAE得到的λ-return，不再混用高方差的整轨迹Monte Carlo Return-to-Go。每次更新同时记录近似KL、新旧比率截断比例、动作饱和比例和Critic解释方差；近似KL超过配置阈值时停止剩余epoch，避免一次rollout上更新过远。

每个转移必须满足同一Cage奖励契约：状态 `s_t` 的前6维是TCP相对 `C_t` 的误差，`C_t` 产生动作 `a_t`，机械臂完成该视觉周期的运动后仍用 `C_t` 计算位置和姿态奖励；周期末的新视觉帧只能产生下一状态中的 `C_(t+1)`。禁止用 `C_(t+1)` 反向评价按 `C_t` 选择的动作。PPO检查点使用格式版本11，同时保存相对状态、独立Actor/Critic、初始化来源、奖励、状态归一化、tanh熵估计和λ-return契约，旧绝对状态策略不能继续加载。

MuJoCo 负责服务器高吞吐训练；Gazebo、ROS Noetic 与 `ros_control` 负责 TF、消息时序、底层伺服和 sim-to-sim 集成验证。MuJoCo位置执行器或`ros_control`在两次视觉事件之间随动跟踪最近发布的关节目标，它们的内部伺服/动力学积分不等于新的PPO决策。没有新视觉事件就没有新PPO动作；目标跳变超过TCP速度包络或关节命令超过限位时，安全层拒绝或限幅。

当前派生 UR5e 的位置执行器按 20 Hz 视觉闭环重新标定。最大 0.45 m/s 目标连续跟踪十个视觉事件时，目标每帧移动约 22.5 mm，实测最大滞后约 7.1 mm、末端滞后约 4.6 mm。相同模型在 10 Hz 时出现约 76 mm 滞后，15 Hz 仍有较多动作饱和；25--30 Hz 虽刷新更快，却缩短每个设定值的底层响应时间且没有改善当前伺服的滞后。因此当前采用 20 Hz 作为这套相机、动作限幅和 MuJoCo 伺服参数的平衡点，而不是假定存在独立的 100 Hz PPO。实体 UR5e 必须重新测量并辨识，不能直接照搬仿真增益。

每50 ms视觉事件的数据顺序固定为“RGB-D完成→Base中心点→Cage当前位姿→相对误差18维状态→一次PPO→立即发布”。五个20 Hz位置点首尾跨越约200 ms历史，但这不是额外等待：每次视觉回调都用已经缓存的 `t-5..t-1` 预测当前 `t`，再把当前观测加入下一次历史。MuJoCo在两个事件之间以MJCF自身的小步长积分位置执行器动力学；实体或实时Gazebo还必须单独测量曝光、传输、检测、TF、PPO推理和伺服响应的墙钟延迟。

`camera` 环境当前包含 PyTorch 2.4.1、MuJoCo 3.2.3 和 Gymnasium 0.29.1。仓库已接入MuJoCo Menagerie UR5e并保留许可证和来源提交，派生场景增加Cage抓子、腕部相机和动态目标。该模型适合算法训练，但仍是公开URDF整理的简化模型；实体部署需要用实际CAD、相机标定和系统辨识参数替换代理值。

## 5. 异常处理与验证

- 静止或近零速度：使用基础半径和稳定历史切线，置信度不足则不生成标签。
- 短时缺帧：按真实时间传播滤波状态；超过陈旧阈值停止新增控制动作。
- 单帧跳变：创新门控拒绝；连续偏移进入重新初始化逻辑。
- 非均匀采样：滤波、速度、半径变化率和关节限制全部使用真实时间。
- 直线转曲线：先保持法向，确认曲率后渐进更新平面。
- 历史不足五帧：只积累，不输出正式 Cage。
- 在线导数不稳：偏向卡尔曼速度、降低置信度并缩短连续延伸。
- 所有候选失败：记录逐级原因并输出无效样本。

轨迹指标包括位置、速度、加速度、切线、曲率和平面误差，端点导数稳定性，以及噪声、异常点、缺帧和不均匀采样鲁棒性。Cage 指标包括几何残差、IK/碰撞通过率、3次EST内部比例均值、六关节变化范数和TCP连续性代价。网络指标包括位置与旋转误差、分速度和分曲率表现。PPO2 指标包括 TCP 跟踪误差、成功时间比例、碰撞率、动作饱和率和关节违规。

信息泄漏必须自动验证：保持五帧历史不变而修改当前及未来观测，当前 Cage 输入和输出应不变；所有历史时间戳必须严格小于标签时间；训练输入生成器不得查询完整离线样条。

## 6. 实现入口

- `generate-trajectories`：生成直线、圆弧、正弦和 Bezier 随机平面轨迹。
- `generate-labels`：完成曲线拟合、候选、筛选、EST、监督数组和 JSONL 审计。
- `generate-vision-dataset`：通过同一UR5e腕部RGB-D链重建五帧监督输入。
- `train-cage`：训练并冻结 20 维输入、六维输出的 Cage MLP。
- `train-ppo`：加载冻结 Cage 与 UR5e MJCF，在 MuJoCo 中训练 PPO2。
- `render-eye`：保存腕部RGB、深度、检测掩码和仿真审计掩码。
- `visualize-system`：让UR5e通过IK到达真实有效标签，联合绘制全臂、腕部相机、小型待抓取Cage、TCP轴、眼在手RGB-D与视觉事件驱动时序。
- `smoke`：执行轨迹到标签的快速闭环。
- `visualize`：绘制未来曲线、平面、候选圆、劣弧、候选姿态、内部区和 EST 节点。
- `ros_ws/src/cage_ppo_ros`：PointStamped 感知、冻结推理和 `ros_control` 关节命令桥。

系统不构造抓子绕根部旋转形成的三维扫掠捕获体；Cage 有效性始终来自抓子真实内部几何，EST 只承担动力学扩展和候选评价。
